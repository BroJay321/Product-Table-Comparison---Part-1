Observation & Comparison

1. Code Readability

  • innerHTML: Highly readable. It uses string templates that look like standard HTML, making it easy to visualize the layout.
  • Direct DOM: Verbose. It requires manual steps for every element created (`createElement`, `textContent`, `appendChild`), which can look cluttered.

2. Execution Behavior

  • innerHTML: Replaces the entire content. The browser must re-parse the string into DOM nodes. It clears any event listeners previously attached to the children.
  • Direct DOM: More efficient for updates. You create nodes in memory and attach them. It is inherently safer against XSS because it treats data as text, not as HTML to be parsed.
